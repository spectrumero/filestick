# CPU test suite

Tests that each unprivileged RV32IMC instruction behaves as the RISC-V
specification says it should. ecall and ebreak (and c.ebreak) aren't
tested, nor are the Zicsr instructions.

It's built with the rest of the software, giving `build/cputest/cputest.elf`.
Copy it to the flash or SD filesystem and run it:

```
*> cputest.elf
RV32IMC CPU tests
74 tests, 74 passed, 0 failed
(FENCE not tested, use -f)
```

| Option | |
|---|---|
| `-v` | List every test as it runs, not just the failures. |
| `-f` | Also test FENCE. A core that doesn't implement FENCE takes an illegal instruction trap, which ends the run, so it's only tested when asked for. |
| *test ...* | Run only the named tests, e.g. `cputest.elf mulhsu c.lw`. Naming `fence` runs it without `-f`. |

A failure shows the test, the case number, and what the instruction produced
compared with what the specification requires:

```
  mulhsu       FAIL case 8: got 0xffffffff, expected 0x00000000
```

To find the case, look in the test's source for the case number. For the
table driven tests in `rv32i_alu.S` and `rv32m.S`, each expected value has a
comment giving its case number and operands.

## What's tested

* Every RV32I, RV32M and RV32C instruction has its own test (`regfile`,
  `branch_far` and `rvc_align` are extra).
* Register usage: rd the same as rs1 or rs2, x0 as a source, x0 as the
  destination (the result must be discarded), and high numbered registers.
  `regfile` checks that all 31 registers hold separate values.
* ALU and M instructions are checked against operand tables covering edge
  cases: 0, 1, -1, the most positive and negative numbers, shift amounts of
  32 and above, division by zero and signed division overflow.
* Loads: sign and zero extension at each byte offset, positive and negative
  offsets including the ±2K extremes, and unaligned base registers.
  Stores: each byte lane, and that neighbouring bytes are left alone.
  Misaligned accesses aren't tested, since the specification lets the
  execution environment decide whether they work or trap.
* Branches and jumps: taken and not taken, forwards and backwards, link
  values, bit 0 of the jalr target being cleared, and the target coming from
  the old value of rs1 when rd is the same register. `branch_far` jumps
  across a 2.7K gap to use immediate bit 11.
* Compressed instructions: register and immediate ranges, maximum offsets,
  and `rvc_align`, which runs 32 bit instructions that straddle a word
  boundary and jumps to them.

## Source files

| File | |
|---|---|
| `main.c` | runs the tests and reports the results |
| `tests.def` | the list of tests |
| `cputest.h` | assembler macros used by the tests |
| `framework.S` | test entry and exit, test data |
| `rv32i_alu.S`, `rv32m.S` | generated by `gen_alu.py`, which computes the expected results |
| `rv32i_mem.S` | loads and stores |
| `rv32i_ctrl.S` | lui, auipc, jumps, branches, register file |
| `rv32c.S` | compressed instructions |
| `fence.S` | FENCE |

The tests are written in assembler so that the exact instruction being
tested is used. In `rv32c.S` the instructions are written with `c.`
mnemonics, so they can only assemble to the compressed encoding. Everywhere
else the instruction under test is assembled with `.option norvc`, so the
assembler can't quietly compress it. Linker relaxation is turned off for all
the test files.

To change the ALU or M cases, edit `gen_alu.py` and run it again
(`python3 gen_alu.py`).
